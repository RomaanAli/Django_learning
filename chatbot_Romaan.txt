1. HIGH-LEVEL SUMMARY: WHAT IS THIS CHATBOT?
================================================================================
Normally, an AI model like ChatGPT or Llama has fixed training data. It has NO idea 
what courses exist on your private website, what their prices are, or who teaches them.
If you simply connect an AI model directly, it will invent (hallucinate) false course 
names, incorrect prices, and non-existent features.

Our chatbot uses RAG (Retrieval-Augmented Generation):
  * "Retrieval": When a student asks a question, our system first queries your 
    own PostgreSQL database and retrieves the exact published course information.
  * "Augmentation": We take those verified course facts and paste them into a 
    strict prompt: "Here are the facts from our database. Answer using ONLY these facts."
  * "Generation": Groq Cloud (running Qwen/Llama) instantly writes a friendly, 
    polite answer citing the exact course title and clickable URL link.

The result: An intelligent, lightning-fast course advisor that NEVER invents fake courses 
and always guides students with real links to your platform!

2. TECHNOLOGIES USED & WHY EACH ONE WAS CHOSEN
================================================================================
1. Django 5.2 (Web Framework):
   - Manages the website, views, URL routing, authentication, and database models.
   - Built with ZERO LangChain. We wrote clean, manual Python so the codebase remains 
     lightweight, transparent, and easy to maintain.

2. PostgreSQL 17 + pgvector (Database & Vector Store):
   - PostgreSQL is already our reliable production database on Render.
   - The `pgvector` extension allows PostgreSQL to store lists of numbers (vectors) 
     and perform geometric similarity calculations directly in SQL with indexed speed.
   - We do not need expensive separate vector databases like Pinecone or Weaviate!

3. sentence-transformers with model "all-MiniLM-L6-v2" (Embedding Engine):
   - Turns any sentence into a list of 384 numbers (an embedding vector) that captures 
     its semantic meaning.
   - Completely free, open-source, and runs directly on your server CPU.
   - Groq does NOT offer an embedding API; `sentence-transformers` handles embeddings locally.

4. Groq Cloud API with model "qwen/qwen3.8-27b" (LLM Generation Engine):
   - Groq uses custom LPU (Language Processing Unit) hardware that generates answers 
     at over 500 tokens per second (nearly instantaneous).
   - High accuracy and reasoning at near-zero operating cost.

5. Django Cache Framework (Rate Limiting & Concurrency Guard):
   - Protects the `/chatbot/ask/` endpoint from abuse (maximum 5 requests per minute per user).
   - Locks the `/chatbot/rebuild-index/` endpoint so two admins cannot rebuild simultaneously.

3. STEP-BY-STEP SETUP GUIDE (LOCAL MACHINE)
================================================================================

Step 1: Activate Virtual Environment
------------------------------------
Open PowerShell in the project directory:
    cd D:\Grayphite\Django_learning
    .\.venv\Scripts\activate

Step 2: Install Required Packages
---------------------------------
Run:
    pip install -r requirements.txt

The three core RAG packages are:
  - `groq==1.7.0` (Client to communicate with Groq Cloud)
  - `sentence-transformers==6.2.0` (Local embedding generator)
  - `pgvector==0.5.1` (Django ORM support for PostgreSQL vector fields)

Step 3: Setup Secret API Key in .env
-----------------------------------
In the project root folder, open `.env`. Ensure you have:
    GROQ_API_KEY=gsk_your_actual_groq_key_here
    GROQ_MODEL=qwen/qwen3.8-27b

*(Get your free key from https://console.groq.com/keys. Do NOT share or commit this key.)*
The file `.env` is listed in `.gitignore` and is NEVER tracked by git.

Step 4: Run Migrations
----------------------
Run:
    python manage.py migrate

This applies `chatbot.0001_initial`:
  - Executes `CREATE EXTENSION IF NOT EXISTS vector;` in PostgreSQL.
  - Creates the `chatbot_knowledgechunk` table (with the 384-d vector field).
  - Creates the `chatbot_chatmessage` table (for conversation history).

Step 5: Index the Knowledge Base
--------------------------------
Run:
    python manage.py build_chatbot_index

This command:
  1. Reads all platform FAQs (how to register, instructor approvals, Stripe payments).
  2. Reads all published courses (`is_published=True`) and their lessons.
  3. Splits text into digestible chunks (300-500 words).
  4. Generates 384-dimensional vector embeddings for each chunk.
  5. Saves all chunks into PostgreSQL.
  Output: "Successfully indexed 55 knowledge chunks into PostgreSQL!"

Step 6: Run the Server & Try the Chatbot
----------------------------------------
Run:
    python manage.py runserver

Open http://127.0.0.1:8000/. You will see the dark-green floating chat bubble in 
the bottom-right corner!

4. STEP-BY-STEP SETUP GUIDE (RENDER CLOUD PRODUCTION)
================================================================================
Render's free tier has no shell access and a temporary filesystem. Our chatbot was 
engineered specifically so that it works seamlessly under these constraints:

Step 1: PostgreSQL on Render
----------------------------
Render's managed PostgreSQL has `pgvector` built-in.
During deployment, your build command (`python manage.py migrate`) automatically 
runs the migration that enables the vector extension in production.

Step 2: Add Environment Variables in Render
-------------------------------------------
1. Open the Render Dashboard -> Select your Web Service.
2. Go to the **Environment** tab.
3. Add:
   - Key: `GROQ_API_KEY` | Value: `gsk_your_live_key...`
   - Key: `GROQ_MODEL`   | Value: `qwen/qwen3.8-27b`
4. Click **Save Changes**.

Step 3: Rebuilding Index in Production (Without Shell Access!)
--------------------------------------------------------------
Since you cannot run `python manage.py build_chatbot_index` via terminal on Render, 
use either of these two built-in methods:

METHOD A (Django Admin - Easiest):
  1. Log into your live site at `https://your-site.onrender.com/admin/`.
  2. Click **Chatbot** -> **Knowledge chunks**.
  3. From the "Action" dropdown, choose:
     "Rebuild Knowledge Base index (embed published courses & FAQs)"
  4. Click **Go**.
  5. The server indexes everything in the background and displays a green success message:
     "Successfully rebuilt knowledge base index! 55 total chunks indexed into pgvector."

METHOD B (Staff Endpoint):
  Authenticated staff or admins can send a POST request with CSRF token to:
     `POST /chatbot/rebuild-index/`
  It returns a clean JSON summary of total chunks indexed.

6. THE MATH MADE SIMPLE: VECTORS, DIMENSIONS & COSINE DISTANCE
================================================================================

Why do we need "vectors" and "embeddings" instead of normal SQL text search (`LIKE '%python%'`)?

1. The Problem with Keyword Search:
   If a user searches: "How can I study coding for beginner developers?"
   A regular database search looks for the exact words "study", "coding", "beginner".
   If your course is titled "Programming Fundamentals for New Learners", regular 
   search FAILS to match because none of the exact words overlap!

2. What is an Embedding Vector?
   The `all-MiniLM-L6-v2` neural network has read billions of texts. It understands 
   that "coding" means the same thing as "programming", and "beginner" means 
   the same thing as "new learner".
   It converts any piece of text into a list of 384 numbers. Each number represents 
   a specific dimension of meaning (e.g., computer science concepts, difficulty level, 
   question intent, tone).

3. What is Cosine Distance?
   Imagine the 384 numbers as coordinates pointing in a 384-dimensional space:
   - If two sentences mean the same thing, their arrows point in the EXACT same direction.
     * The angle between them is 0 degrees.
     * Cosine Distance = 0.0 (Perfect Match).
   - If two sentences are completely unrelated (e.g., "Django web development" vs 
     "chocolate chip recipe"):
     * Their arrows point in completely different directions.
     * Cosine Distance = 0.85 to 1.0 (Completely Unrelated).

4. Our 0.70 Guardrail Threshold:
   In `chatbot/retrieval.py`, we set `DISTANCE_THRESHOLD = 0.70`.
   - Distance <= 0.70: Good match! We pass the text to Groq.
   - Distance > 0.70: Irrelevant! The system refuses to hallucinate and delivers 
     the polite fallback message directly, saving money and preserving accuracy.

7. FILE-BY-FILE BREAKDOWN & INTERCONNECTIONS
================================================================================

Let's inspect every single file in the chatbot ecosystem and how they link together:

1. `chatbot/models.py`:
   - `KnowledgeChunk`:
     * `source_type`: 'course', 'lesson', or 'faq'
     * `source_id`: ID of the course or lesson (or empty for FAQ)
     * `title`: Human-readable chunk title (e.g. "Lesson: Python Syntax")
     * `content`: The chunk text (about 300 to 500 words)
     * `source_url`: URL where the user can view the full course (e.g. "/courses/2/")
     * `embedding`: `VectorField(dimensions=384)` from pgvector
   - `ChatMessage`:
     * `user`: Foreign key to `accounts.User`
     * `role`: 'user' or 'assistant'
     * `content`: The text message
     * `created_at`: Timestamp

2. `chatbot/retrieval.py`:
   - Uses Python singleton pattern: loads the embedding model `all-MiniLM-L6-v2` 
     into memory once when the server boots.
   - `retrieve_relevant_chunks(query, top_k=4)`:
     1. Encodes the user query string into a 384-d vector.
     2. Runs `KnowledgeChunk.objects.annotate(distance=CosineDistance("embedding", vector)).order_by("distance")[:4]`.
     3. Checks if `best_distance <= 0.70`.
     4. Returns a dictionary containing the matching chunks, source URLs, and distance metrics.

3. `chatbot/faqs.py`:
   - Contains a curated list of static platform knowledge dictionaries:
     * FAQ 1: How to register as a student vs instructor.
     * FAQ 2: Shared login page and email/password requirements.
     * FAQ 3: Instructor document upload and pending admin approval.
     * FAQ 4: How to enroll in free courses.
     * FAQ 5: How paid courses work via Stripe checkout.
     * FAQ 6: Where to browse courses and access lesson content.
     * FAQ 7: Student and Instructor profile dashboards.

4. `chatbot/management/commands/build_chatbot_index.py`:
   - The engine that populates `KnowledgeChunk`.
   - Iterates through `chatbot/faqs.py` and published `courses.models.Course`.
   - Slices text into overlapping windows (chunks of 300-500 words with 50-word overlap) 
     so sentences are never cut awkwardly in the middle.
   - Encodes them in batches of 32 for maximum CPU efficiency.
   - Idempotent: completely deletes old chunks and inserts fresh ones in a clean bulk operation.

5. `chatbot/views.py`:
   - `ask_chatbot(request)`:
     * Verifies user login, length <= 500 chars, rate limit 5 req/min.
     * Checks `_handle_personal_question`: If the student asks about their own 
       enrollments, answers via `courses.models.Enrollment` directly.
     * Calls `retrieve_relevant_chunks(cleaned_message)`.
     * If no chunks pass threshold: returns fallback message immediately.
     * If chunks match: calls `groq.Groq(api_key=settings.GROQ_API_KEY)`.
     * Saves user message and assistant message to `ChatMessage`.
     * Returns JSON `{"answer": ..., "sources": [...]}`.
   - `rebuild_index(request)`:
     * Staff/Admin only view.
     * Checks cache lock `chatbot_rebuild_index_lock` to prevent double execution.
     * Calls `call_command('build_chatbot_index')`.
     * Returns JSON summary of total chunks active.

6. `chatbot/urls.py` & `E_learning/urls.py`:
   - `E_learning/urls.py` delegates all `/chatbot/*` requests:
     `path("chatbot/", include("chatbot.urls"))`
   - `chatbot/urls.py` maps:
     * `/chatbot/ask/` -> `views.ask_chatbot`
     * `/chatbot/rebuild-index/` -> `views.rebuild_index`

7. `chatbot/admin.py`:
   - Registers `KnowledgeChunkAdmin` and `ChatMessageAdmin` in Django Admin.
   - Adds the admin action `rebuild_knowledge_chunks` so administrators can 
     click one button on Render to rebuild the entire AI knowledge base.

8. `chatbot/templates/chatbot/widget.html`:
   - Standalone floating HTML/CSS/JavaScript component included in `core/templates/base.html`.
   - Features:
     * Floating toggle button at bottom-right with smooth expand animation.
     * Fully responsive: 380px wide on desktop; full screen width with 16px margins on mobile.
     * Animated 3-dot typing indicator while Groq is thinking.
     * Regex link parser that turns `[Link Title](/url/)` into clickable links.
     * Clickable source badges at the bottom of answers.
     * Disables input and shows a login link if the user is unauthenticated.

9. `chatbot/tests.py`:
   - Automated Django test suite verifying permissions and endpoint stability:
     * `test_anonymous_user_blocked` (Verifies 401 on unauthenticated rebuild)
     * `test_student_user_forbidden` (Verifies 403 on regular student)
     * `test_staff_user_can_trigger_rebuild_success` (Verifies 200 on staff)
     * `test_admin_action_triggers_rebuild` (Verifies Django Admin action)

8. 5 REAL-LIFE SCENARIOS: COMPLETE STEP-BY-STEP EXECUTION TRACES
================================================================================

--------------------------------------------------------------------------------
SCENARIO A: Student asks: "What topics are covered in the Python course?"
--------------------------------------------------------------------------------
1. Student types question in widget and clicks Send.
2. JavaScript sends POST to `/chatbot/ask/` with CSRF cookie.
3. `views.py` validates: User is logged in, length is 46 chars, rate limit OK.
4. Not a personal question (no "my courses" keywords).
5. `retrieval.py` converts "What topics are covered in the Python course?" to 384 numbers.
6. pgvector finds top chunk: "Course: Complete Python Bootcamp" with distance 0.28 (Strong match!).
7. Distance 0.28 <= 0.70 threshold -> Proceed to Groq.
8. Groq receives the prompt with the exact Python course chunk and syllabus.
9. Groq writes:
   "The Complete Python Bootcamp covers programming fundamentals, data structures, 
   object-oriented programming, and working with libraries. 
   You can view the full curriculum here: [Complete Python Bootcamp](/courses/1/)."
10. Answer is saved to `ChatMessage`.
11. Widget displays the answer, turns the link clickable, and adds a badge:
    `[Source: Course: Complete Python Bootcamp]`.

--------------------------------------------------------------------------------
SCENARIO B: Student asks: "tell me how many course i have enrolled"
--------------------------------------------------------------------------------
1. Student sends question to `/chatbot/ask/`.
2. `views.py` inspects question with `_handle_personal_question()`.
3. Detects pattern: matches enrollment query!
4. `views.py` queries database:
   `Enrollment.objects.filter(student=request.user).select_related("course")`
5. Returns instant answer from database with exact enrolled count and links.
6. Notice: Groq API was NEVER called, and the vector DB was NEVER searched!
   The answer is 100% accurate, instant, and private.

--------------------------------------------------------------------------------
SCENARIO C: Student asks: "Can you give me a recipe for chocolate cake?"
--------------------------------------------------------------------------------
1. Student sends question to `/chatbot/ask/`.
2. `views.py` passes text to `retrieval.py`.
3. pgvector evaluates all chunks. The closest chunk is about platform registration 
   with distance 0.84.
4. Threshold check: 0.84 > 0.70 (Out of Scope!).
5. View DOES NOT call Groq.
6. View immediately returns the fallback answer:
   "I don't have information about that. I can help you with course details, 
   enrollment, payments, and how to use the site."
7. Zero tokens wasted, zero hallucination.

--------------------------------------------------------------------------------
SCENARIO D: Anonymous Visitor opens the chat
--------------------------------------------------------------------------------
1. Visitor visits homepage http://127.0.0.1:8000/.
2. Widget loads at bottom-right.
3. Django template tags evaluate: `{% if user.is_authenticated %}` is FALSE.
4. Widget displays:
   "Welcome to E-Learning! I can answer questions about published courses, lessons, 
   pricing, and how the platform works."
5. At the bottom, input area is replaced by:
   "Please log in to ask questions to the assistant. [Log In link]"
6. If an external attacker attempts to directly POST to `/chatbot/ask/`, 
   `views.py` blocks it immediately with `401 Unauthorized`.

--------------------------------------------------------------------------------
SCENARIO E: Admin Rebuilds the Index on Render
--------------------------------------------------------------------------------
1. Instructor publishes a brand new course: "Advanced Docker for Developers".
2. Admin logs into https://your-site.onrender.com/admin/.

   - Generates embeddings for the new course and its lessons.
   - Bulk-inserts them into `chatbot_knowledgechunk`.
5. Django admin displays:
   "Successfully rebuilt knowledge base index! 62 total chunks indexed into pgvector."
6. The chatbot can now immediately answer questions about the new Docker course!

9. SECURITY, PRIVACY & GUARDRAILS
================================================================================
1. Zero Sensitive Data Exposure:
   - User passwords, password reset tokens, and email OTPs are NEVER indexed.
   - Stripe credit card details and webhook secrets are NEVER indexed.
2. Only Published Courses are Indexed:
   - Courses with `is_published=False` (drafts or under review) are strictly excluded.
3. Personal Data Isolation:
   - Personal questions are resolved strictly through Django ORM and scoped to `request.user`.
   - One student can NEVER see or retrieve another student's enrollments.
4. Rate Limiting:
   - 5 requests per minute per user via Django cache prevents denial of service.
5. Max Input Length:
   - 500 characters maximum prevents prompt injection and token flooding.
