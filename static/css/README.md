# Tailwind CSS v4 — Build Workflow

## Local development

1. Download the Tailwind v4 standalone CLI binary for your platform:
   - macOS: `tailwindcss-macos-arm64` or `tailwindcss-macos-x64`
   - Linux: `tailwindcss-linux-x64`
   - Windows: `tailwindcss-windows-x64.exe`
   From: https://github.com/tailwindlabs/tailwindcss/releases/tag/v4.1.7

2. Make it executable (`chmod +x tailwindcss` on macOS/Linux).

3. Compile CSS:
   ```
   ./tailwindcss -i static/css/input.css -o static/css/output.css --minify
   ```

4. Re-run the command whenever you edit `static/css/input.css` or Tailwind classes in templates.

## Render production build

The `render.yaml` build command automatically:
1. Installs Python dependencies from `requirements.txt`
2. Downloads the Tailwind v4 standalone Linux binary (`tailwindcss-linux-x64`)
3. Compiles `static/css/input.css` → `static/css/output.css` with `--minify`
4. Runs `python manage.py collectstatic --noinput` (WhiteNoise serves the compiled CSS)

Order matters: CSS is compiled **before** `collectstatic` so production always serves fresh styles.

## File layout

- `static/css/input.css` — Tailwind entry file with `@import "tailwindcss"` and `@theme` tokens
- `static/css/output.css` — compiled output (git-ignored, generated by build)
- `static/css/README.md` — this file
